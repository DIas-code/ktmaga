# Подготовка к КТ в магистратуру — М094 «Информационные технологии»

Сайт с конспектами и тренажёром тестов по четырём блокам комплексного тестирования.

```
KTmaga/
├── Английский язык.pdf                                исходные спецификации ЦЕНТ
├── Тест_на_определение_готовности_к_обучению.pdf
├── Bazy_Dannykh_Spetsifikatsia_Testa.doc
├── Algoritmy_I_Struktury_Dannykh_Spetsifikatsia_Testa.docx
└── web/                                               сайт (Next.js)
```

## Запуск

```bash
cd web
npm install
npm run dev      # http://localhost:3000
```

| Команда | Что делает |
|---|---|
| `npm run dev` | Дев-сервер |
| `npm run build` | Продакшен-сборка (весь сайт статический, 84 страницы) |
| `npm run start` | Запуск собранного сайта |
| `npm run lint` | ESLint |
| `npm run check` | Проверка контента: индексы ответов, ссылки на темы, соответствие банка вопросов спецификации |
| `npm run variants` | Пересобрать готовые варианты тестов после изменения банка |
| `npm run coverage` | Показать, на сколько полных вариантов хватает банка |
| `npm run images -- <ocr.json>` | Пересобрать таблицу «задание → скриншот пробника» |

### Откуда взято каждое задание

Под условием каждого задания показан путь к исходнику в папке `Пробники`.
Путь без значка — задание найдено на конкретном скриншоте; со значком `≈` —
точный файл не установлен, указано только откуда шёл импорт.

Соответствие «задание → файл» при импорте банка не сохранялось, поэтому оно
восстановлено обратным ходом: текст всех 2651 скриншота распознан встроенным
OCR Windows, а затем каждое задание сопоставлено со скриншотами по совпадению
триграмм в скользящем окне. Результат лежит в `web/src/content/question-images.ts`
и в репозиторий входит готовым — пересобирать его нужно только при изменении
банка, и для этого нужна папка `Пробники`, которой в репозитории нет.

Сопоставлено 131 задание из 5776. Больше и не выйдет: основная часть банка
пришла не со скриншотов, а из двух Word-документов с ключами ответов
(`Сливы бейба/Алгоритм-рус.docx`, `База_данных_ru.docx`), и картинок для этих
заданий не существует.

## Четыре режима работы

| Режим | Что это |
|---|---|
| **Готовые варианты** (`/<предмет>/variants`) | По 5 зафиксированных вариантов на предмет. Состав не меняется между попытками: можно пройти, разобрать ошибки и вернуться к тому же набору |
| **Случайный вариант** (`/<предмет>/exam`) | Собирается заново из **всего** банка по правилам спецификации — каждый раз новый набор |
| **Тренировка** (`/<предмет>/practice`) | Выбор тем и уровней, без таймера, разбор сразу после каждого ответа |
| **Все задания** (`/<предмет>/questions`) | Просмотр всего банка: фильтр по теме и уровню, поиск по тексту, показ ответа и разбора |

Банки по алгоритмам и БД весят по паре мегабайт, поэтому страница просмотра
подгружает их отдельным JS-чанком (`src/content/client-banks.ts`), а не вкладывает
в HTML: сама страница остаётся около 115 КБ вместо 2,3 МБ.

Готовые варианты собираются скриптом `scripts/build-variants.ts` строго по плану
спецификации: по каждой теме берётся ровно столько заданий каждого уровня, сколько
положено. Приоритет отдаётся заданиям, восстановленным из пробников ЦЕНТ.
Файлы `src/content/*/variants.ts` **генерируются** — править их вручную не нужно.

## Состояние разделов

| Блок | Заданий | Время | Конспекты | Банк вопросов | Готовых вариантов |
|---|---|---|---|---|---|
| Английский язык | 100 | 125 мин | 13 из 13 | **480** | 5 (90% из пробников) |
| Готовность к обучению | 30 | 50 мин | 6 из 6 | **258** | 5 (100% из пробников) |
| Базы данных | 20 | 50 мин | 14 из 14 | **2141** | 5 (100% из пробников) |
| Алгоритмы и структуры данных | 30 | 60 мин | 10 из 10 | **2897** | 5 (100% из пробников) |

Всего **5776 заданий**, у каждого есть ответ и разбор.

Источники банка помечены префиксами идентификаторов:

| Префикс | Откуда |
|---|---|
| без префикса | составлено под спецификацию |
| `ct-*` | восстановлено по скриншотам пробного тестирования ЦЕНТ |
| `kb-*` | отобрано из банков с готовыми ключами (DOCX и PDF) |
| `hi-*` | история и авторы алгоритмов и моделей |

Отмеченные на скриншотах ответы не принимались на веру: примерно 15% из них неверны.
Подробности разбора — в `ПРОГРЕСС-ПРОБНИКИ.md`.

**Блок аудирования** (32 задания из 100 по английскому) тренажёром не покрывается: задания строятся на прослушивании записей, которых у проекта нет, а «слушать» текст на экране — значит проверять чтение. Тема помечена в коде полем `noBank`, исключается из пробного варианта, и причина показывается пользователю. Конспект с устройством блока и стратегией подготовки при этом есть.

## Правила тестов (из официальных спецификаций)

**Английский язык** — 100 заданий, 125 минут, **один ответ из четырёх**, 1 балл.
Три отдельно хронометрируемых блока: аудирование 32 задания / 45 мин, лексико-грамматический 32 / 30 мин, чтение 36 / 50 мин. Распределение по уровням 34 / 33 / 33. В аудировании и чтении буквы A/B/C означают **уровень понимания** (фрагментарное, детальное, глобальное), а не трудность. Итоговый уровень владения (A1…C) определяется по доле верных ответов на каждом языковом уровне отдельно.

**Готовность к обучению** (с 2024 года) — 30 заданий, 50 минут, **один ответ из пяти или четырёх**, 1 балл.
Два раздела: критическое мышление (15 заданий) и аналитическое мышление (15). Отдельного времени на разделы спецификация не задаёт.

**Базы данных** (с 2022 года) — 20 заданий, 50 минут, закрытая форма с выбором **одного или нескольких** правильных ответов.
Оценивание: все верные — 2 балла, одна ошибка — 1 балл, две и более — 0. Ошибкой считается и лишний выбранный вариант, и пропущенный верный.

**Алгоритмы и структуры данных** (с 2022 года) — 30 заданий, 60 минут, **один ответ из пяти**, 1 балл.

Во всех блоках, кроме английского, распределение по трудности: A — 30%, B — 40%, C — 30%.

## Как добавить контент

**Конспект темы** — markdown-файл `web/src/content/<раздел>/theory/<slug-темы>.md`. Появляется на странице темы автоматически. Поддерживаются таблицы GFM и подсветка кода.

**Вопросы** — массив в `web/src/content/<раздел>/questions.ts`:

```ts
{
  id: "db-jn-5",                    // уникальный
  topic: "joins",                   // slug темы из meta.ts
  difficulty: "B",                  // A | B | C
  text: "Что верно о …?",
  code: { lang: "sql", value: "SELECT …" },      // необязательно
  passage: { title: "Text 1", value: "…" },      // необязательно: текст для чтения
  options: ["…", "…", "…", "…", "…"],            // столько, сколько разрешает optionCounts
  correct: [0, 2],                  // индексы верных; при single — ровно один
  explanation: "Почему именно так.",
}
```

После правок — `npm run check`: он ловит битые ссылки на темы, индексы вне диапазона, вырожденные задания, дубликаты id, недопустимое число вариантов и расхождение плана по темам со спецификацией.

**Новая спецификация** — заполнить `spec` и `topics` в `web/src/content/<раздел>/meta.ts` и переключить `ready: true`. Сумма `plan` по темам должна совпадать с `totalQuestions`, `difficultyMix` и, если заданы, с `blocks` — `npm run check` это проверяет.

## Устройство

- **Next.js 16 (App Router), React 19, Tailwind v4** — весь сайт пререндерится в статику, сервер для работы не нужен.
- **Модель контента:** `Subject` → `ExamBlock` (необязательно) → `Topic` → `plan` по уровням A/B/C. План каждой темы взят из таблицы спецификации, поэтому пробный вариант собирается по тем же правилам, что и настоящий.
- **Сборка варианта** — `web/src/lib/exam.ts`. Если в банке не хватает заданий по теме, недобор компенсируется заданиями того же уровня из других тем: распределение A/B/C сохраняется. Темы с `noBank` в подсчёте не участвуют вовсе — подменять аудирование грамматикой было бы враньём, и об исключении сообщается явно.
- **Блочные экзамены** доступны там, где спецификация задаёт блоку собственное время (английский): можно сдать отдельно лексико-грамматический блок или блок чтения со своим таймером.
- **Подсчёт баллов** — `gradeAnswer`, отдельно для схемы с несколькими верными ответами (БД) и для схемы с одним.
- Прогресс и история попыток хранятся в `localStorage` браузера, на сервер ничего не уходит.
