## Определения, которые спрашивают дословно

| Термин | Формулировка в тесте |
|---|---|
| **Граф** | Множество точек (вершин) вместе с набором линий (рёбер), которые соединяют определённые пары вершин |
| **Смежные вершины** | Две вершины в графе, соединяющие ребро |
| **Поиск в ширину** | Алгоритм стремится держаться как можно ближе к исходной вершине, посещает все вершины, смежные с исходной, и только после этого отходит дальше |
| **Поиск в глубину** | Стратегия поиска, состоящая в том, чтобы идти «вглубь» графа, насколько это возможно |
| **Алгоритм Прима** | Построение минимального остовного дерева взвешенного связного неориентированного графа |
| **Топологическая сортировка** | Поиск такого способа упорядочивания терминов в словаре, чтобы никакой термин не использовался до того, как он будет определён |

> «Соседние вершины» — разговорный вариант, в определении используется слово **смежные**.
> Различайте по ключевому слову: «ближе к исходной» → ширина, «вглубь» → глубина.

## Основные понятия

**Граф** G = (V, E): множество вершин V и множество рёбер E.

- **Неориентированный** — рёбра без направления; **ориентированный** (орграф) — дуги направлены.
- **Взвешенный** — рёбрам приписаны веса.
- **Степень вершины** — число инцидентных рёбер; в орграфе различают входящую и исходящую.
- **Путь** — последовательность вершин, соединённых рёбрами. **Цикл** — путь, начинающийся и заканчивающийся в одной вершине.
- **Связный граф** — между любой парой вершин есть путь.
- **Дерево** — связный ациклический граф; на V вершинах содержит ровно **V − 1** ребро.
- **Плотный граф** — E ≈ V²; **разреженный** — E ≈ V.

## Способы представления

| Представление | Память | Проверка ребра | Обход соседей |
|---|---|---|---|
| **Матрица смежности** | O(V²) | **O(1)** | O(V) |
| **Списки смежности** | **O(V + E)** | O(степени) | **O(степени)** |
| Список рёбер | O(E) | O(E) | O(E) |

**Один и тот же граф в двух представлениях:**

```
       граф                матрица смежности        списки смежности
                              0 1 2 3 4
      0 ─── 1               0 │0 1 1 0 0│           0 → 1 → 2
      │   ╱ │               1 │1 0 1 1 0│           1 → 0 → 2 → 3
      │  ╱  │               2 │1 1 0 0 1│           2 → 0 → 1 → 4
      2     3               3 │0 1 0 0 0│           3 → 1
      │                     4 │0 0 1 0 0│           4 → 2
      4
                          25 ячеек на 5 вершин      хранится ровно 2E ссылок
                          (V² независимо от рёбер)  (растёт вместе с рёбрами)
```

```c
// Матрица смежности
int g[V][V];
g[u][v] = 1;                     // ребро u→v

// Списки смежности
typedef struct Edge { int to, w; struct Edge *next; } Edge;
Edge *adj[V];
```

**Вывод:** для разреженного графа списки смежности экономят память драматически — **O(V + E)** против **O(V²)**. Разница не косметическая: у социального графа на миллион пользователей с сотней друзей у каждого списки займут порядка 10⁸ ссылок, а матрица потребовала бы 10¹² ячеек, почти целиком заполненных нулями. Для плотного графа и при частой проверке «есть ли ребро» удобнее матрица — она отвечает за **O(1)**, тогда как списку надо пробежать соседей.

## Поиск в ширину (BFS)

Обходит вершины **по слоям**: сначала все соседи стартовой вершины, затем соседи соседей, и так далее. Ключ к пониманию — **очередь**: вершины выходят из неё в том же порядке, в каком вошли, поэтому весь слой обрабатывается прежде, чем алгоритм заглянет на следующий. Именно из-за послойности BFS находит кратчайший путь по числу рёбер: вершина попадает в очередь ровно тогда, когда до неё дотянулся ближайший слой.

**Обход от вершины 0:**

```
        (0)         слой 0:  0
       ╱   ╲        слой 1:  1, 2
     (1)   (2)      слой 2:  3, 4
     ╱ ╲     ╲      слой 3:  5
   (3) (4)   (5)

    очередь        снимаем   добавляем        посещено
    ───────────────────────────────────────────────────
    [0]              0        1, 2            0
    [1, 2]           1        3, 4            0 1
    [2, 3, 4]        2        5               0 1 2
    [3, 4, 5]        3        —               0 1 2 3
    [4, 5]           4        —               0 1 2 3 4
    [5]              5        —               0 1 2 3 4 5
    []                                        готово

    порядок обхода: 0 1 2 3 4 5   ← слой за слоем
```

> Вершина помечается посещённой **при добавлении в очередь**, а не при извлечении.
> Иначе одна и та же вершина попадёт в очередь несколько раз через разных соседей.

```c
void bfs(int start, int n) {
    int visited[n]; memset(visited, 0, sizeof(visited));
    Queue q; init(&q);
    visited[start] = 1;
    enqueue(&q, start);
    while (!is_empty(&q)) {
        int v = dequeue(&q);
        printf("%d ", v);
        for (Edge *e = adj[v]; e; e = e->next)
            if (!visited[e->to]) {
                visited[e->to] = 1;   // помечаем при ДОБАВЛЕНИИ в очередь
                enqueue(&q, e->to);
            }
    }
}
```

**Сложность:** O(V + E) со списками смежности, O(V²) с матрицей.

**Применения:** кратчайший путь в **невзвешенном** графе (по числу рёбер), проверка связности, поиск компонент, проверка двудольности, обход по уровням.

## Поиск в глубину (DFS)

Уходит вглубь до упора, а когда идти больше некуда — **возвращается назад** (backtracking) к последней вершине, где остался неисследованный сосед. Использует **стек** — явный или неявный, через рекурсию. Отличие от BFS ровно в структуре данных: очередь даёт послойный обход, стек — обход «по одной ветке до конца».

**Тот же граф, обход от вершины 0:**

```
        (0)              1. идём 0 → 1 → 3, дальше тупик
       ╱   ╲             2. откат в 1, идём в 4, тупик
     (1)   (2)           3. откат в 1, потом в 0, идём в 2 → 5
     ╱ ╲     ╲
   (3) (4)   (5)

    стек          текущая   действие                посещено
    ────────────────────────────────────────────────────────
    [0]             0       вглубь → 1              0
    [0,1]           1       вглубь → 3              0 1
    [0,1,3]         3       тупик, откат            0 1 3
    [0,1]           1       вглубь → 4              0 1 3
    [0,1,4]         4       тупик, откат            0 1 3 4
    [0]             0       вглубь → 2              0 1 3 4
    [0,2]           2       вглубь → 5              0 1 3 4 2
    [0,2,5]         5       тупик, откат до конца   0 1 3 4 2 5

    порядок обхода: 0 1 3 4 2 5   ← ветка за веткой
```

**BFS и DFS на одном графе дают разный порядок**: `0 1 2 3 4 5` против `0 1 3 4 2 5`. Это типовое задание — не перепутайте, какая структура данных у какого обхода.

```c
void dfs(int v, int *visited) {
    visited[v] = 1;
    printf("%d ", v);
    for (Edge *e = adj[v]; e; e = e->next)
        if (!visited[e->to]) dfs(e->to, visited);
}
```

**Сложность:** O(V + E).

**Применения:** поиск циклов, топологическая сортировка, компоненты сильной связности (Косарайю, Тарьян), поиск мостов и точек сочленения, решение лабиринтов и задач с перебором.

> В спецификации дисциплины сокращения BFS и DFS указаны с перепутанными расшифровками. Правильно: **BFS** (breadth-first search) — поиск **в ширину**, очередь; **DFS** (depth-first search) — поиск **в глубину**, стек.

## Кратчайшие пути

| Алгоритм | Задача | Сложность | Отрицательные веса |
|---|---|---|---|
| **BFS** | Один источник, невзвешенный | O(V + E) | — |
| **Дейкстры** | Один источник | O((V+E) log V) с кучей | **Нет** |
| **Беллмана — Форда** | Один источник | O(V·E) | **Да**, обнаруживает отрицательные циклы |
| **Флойда — Уоршелла** | **Все пары** | **O(V³)** | Да (без отрицательных циклов) |

### Алгоритм Дейкстры

Жадный: на каждом шаге берётся ещё не обработанная вершина с минимальным известным расстоянием, и через неё релаксируются рёбра.

```c
// Схема
dist[start] = 0; остальные = ∞
пока есть необработанные вершины:
    v = вершина с минимальным dist среди необработанных
    пометить v обработанной
    для каждого ребра (v → u) весом w:
        если dist[v] + w < dist[u]: dist[u] = dist[v] + w
```

**Трассировка от вершины A:**

```
         4        1
    (A)────(B)────(C)
     │  ╲     ╲    │
    2│   5╲    3╲  │ 1
     │      ╲    ╲ │
    (D)──────────(E)
           7

    шаг  берём  dist[A] dist[B] dist[C] dist[D] dist[E]   обработано
    ────────────────────────────────────────────────────────────────
     0     —       0       ∞       ∞       ∞       ∞      —
     1     A       0       4       ∞       2       5      A
     2     D       0       4       ∞       2       5      A D      (2+7=9 > 5, не лучше)
     3     B       0       4       5       2       5      A B D    (4+1=5 → C)
     4     C       0       4       5       2       5      A B C D  (5+1=6 > 5)
     5     E       0       4       5       2       5      всё

    кратчайшие пути из A:  B=4, C=5, D=2, E=5
```

На каждом шаге берётся ближайшая **необработанная** вершина — это и есть жадность. Она обоснована тем, что при неотрицательных весах путь не может стать короче, если пойти в обход через более далёкую вершину.

**Не работает с отрицательными весами.** Зафиксировав вершину как обработанную, алгоритм к ней не возвращается, а отрицательное ребро могло бы позже дать более короткий путь:

```
    (A)──1──▶(B)          Дейкстра зафиксирует B = 1 сразу,
     │         ▲          хотя путь A → C → B = 4 + (−5) = −1 короче.
     4         │          Ошибку он уже не исправит.
     │        −5
     ▼         │
    (C)────────┘
```

**Сложность.** Реализация на массиве — **O(V²)** (хороша для плотных графов, где E ≈ V²), на приоритетной очереди — **O((V + E) log V)** (для разреженных). Каждая вершина извлекается один раз, каждое ребро релаксируется один раз.

### Алгоритм Беллмана — Форда

Релаксирует **все рёбра** V − 1 раз.

```c
for (int i = 0; i < V - 1; i++)
    for (каждое ребро (u, v, w))
        if (dist[u] + w < dist[v]) dist[v] = dist[u] + w;

// V-й проход: если что-то ещё улучшается — есть отрицательный цикл
```

Медленнее Дейкстры — O(V·E), — но допускает отрицательные веса и **обнаруживает отрицательные циклы**.

### Алгоритм Флойда — Уоршелла

Динамическое программирование, матрица расстояний между **всеми парами**:

```c
for (int k = 0; k < n; k++)          // k — промежуточная вершина, ВНЕШНИЙ цикл
    for (int i = 0; i < n; i++)
        for (int j = 0; j < n; j++)
            if (d[i][k] + d[k][j] < d[i][j])
                d[i][j] = d[i][k] + d[k][j];
```

**O(V³)** по времени, O(V²) по памяти. Порядок циклов важен: k обязан быть внешним.

## Минимальное остовное дерево (MST)

Подмножество рёбер, соединяющее все вершины связного графа без циклов, с минимальной суммой весов. Всегда содержит **V − 1** ребро.

### Алгоритм Прима

Растит **одно связное поддерево**: начинает с произвольной вершины и каждый раз добавляет минимальное ребро, соединяющее дерево с внешней вершиной.

Сложность: O(V²) на массиве, O(E log V) с приоритетной очередью. Хорош для **плотных** графов.

### Алгоритм Крускала

Сортирует **все рёбра** по возрастанию веса и добавляет их по очереди, пропуская те, что образуют цикл. Проверка цикла — через систему непересекающихся множеств (DSU).

```
отсортировать рёбра по весу
для каждого ребра (u, v):
    если find(u) != find(v):        // ещё не в одной компоненте
        добавить ребро в MST
        union(u, v)
```

Сложность: **O(E log E)** — доминирует сортировка. Хорош для **разреженных** графов.

| | Прим | Крускал |
|---|---|---|
| Стратегия | Наращивание дерева от вершины | Слияние компонент по рёбрам |
| Структура | Приоритетная очередь | DSU + сортировка |
| Сложность | O(E log V) | O(E log E) |
| Лучше подходит | Плотным графам | Разреженным графам |

Оба дают MST с одинаковым **суммарным весом**, но порядок добавления рёбер разный, а при равных весах могут получиться разные (одинаково минимальные) деревья.

## Виды графов — полная картина

| Признак | Виды |
|---|---|
| Направленность | Неориентированный, ориентированный (орграф), смешанный |
| Веса | Взвешенный, невзвешенный |
| Кратные рёбра | Простой граф, мультиграф |
| Петли | С петлями, без петель |
| Связность | Связный, несвязный; для орграфа — сильно и слабо связный |
| Плотность | Плотный (E ≈ V²), разреженный (E ≈ V) |
| Циклы | Циклический, ациклический (DAG) |
| Полнота | Полный (все пары соединены), неполный |
| Особые | Двудольный, планарный, дерево, лес |

**Полный граф** на V вершинах имеет V(V−1)/2 рёбер (неориентированный).
**Двудольный граф** — вершины делятся на два множества, рёбра идут только между ними;
опознаётся раскраской в два цвета обходом в ширину.

**Степень вершины** — число инцидентных рёбер. Сумма степеней всех вершин равна 2E:
каждое ребро добавляет по единице к двум вершинам. В орграфе различают
входящую и исходящую степень.

**Путь** — последовательность вершин, соединённых рёбрами. **Простой путь** не повторяет
вершин. **Цикл** — путь, начинающийся и заканчивающийся в одной вершине.
**Эйлеров цикл** проходит по каждому РЕБРУ ровно один раз, **гамильтонов** — через
каждую ВЕРШИНУ ровно один раз. Первый проверяется за линейное время, второй — НП-полная задача.

## Связность

**Компонента связности** — максимальное подмножество вершин, попарно достижимых друг
из друга. Находится запуском обхода (BFS или DFS) из каждой непосещённой вершины: O(V + E).

Для орграфа различают:
- **слабую связность** — граф связен, если игнорировать направления;
- **сильную связность** — из любой вершины достижима любая другая с учётом направлений.
Компоненты сильной связности находят алгоритмами Косарайю или Тарьяна за O(V + E).

**Мост** — ребро, удаление которого увеличивает число компонент связности.
**Точка сочленения** — вершина с тем же свойством. Оба находятся модификацией DFS.

## Топологическая сортировка

Линейный порядок вершин ориентированного **ациклического** графа (DAG), при котором каждое ребро направлено «вперёд».

Два способа: DFS с выводом вершин в обратном порядке завершения, либо алгоритм Кана (последовательное удаление вершин с нулевой входящей степенью). Оба — O(V + E).

Применения: порядок сборки, планирование задач с зависимостями, разрешение зависимостей пакетов.

| Утверждение | |
|---|---|
| BFS — очередь, DFS — стек | ✔ |
| BFS и DFS — O(V + E) | ✔ |
| Дейкстра не работает с отрицательными весами | ✔ |

| Списки смежности: O(V + E); матрица: O(V²) | ✔ |

## Быстрая проверка себя

1. Какую структуру использует BFS? *(очередь)*
2. Какой алгоритм кратчайших путей допускает отрицательные веса? *(Беллмана — Форда)*
3. Сложность алгоритма Флойда — Уоршелла? *(O(V³))*
4. Сколько рёбер в остовном дереве графа из 10 вершин? *(9)*
5. Какое представление выгоднее для разреженного графа? *(списки смежности)*
