## Определения, которые спрашивают дословно

Большинство заданий темы — «определение → термин». Запомните формулировки.

| Термин | Формулировка в тесте |
|---|---|
| **Дерево** | Конечное множество одного или более узлов, если существует выделенный узел — корень, а остальные распределены среди непересекающихся множеств (поддеревьев) |
| **Лес** | Множество, не содержащее ни одного дерева или содержащее несколько непересекающихся деревьев |
| **Поддерево** | Часть одного дерева, растущая из некоторого узла |
| **Уровень корня** | Равен **нулю** |
| **Бинарное дерево** | В каждом узле — **два указателя связи** |
| **AVL-дерево** | Сбалансированное двоичное дерево поиска, у которого для каждой вершины высота её двух поддеревьев различается не более чем на 1 |
| **Подобные деревья** | Совпадает структура |
| **Эквивалентные деревья** | Совпадает и структура, и хранимая информация |
| **Внешний внук** | Находится на той же стороне от своего родителя, что и его родитель по отношению к своему родителю |
| **Внутренний внук** | Направления «прародитель → родитель» и «родитель → внук» противоположны |
| **Последний узел пирамиды** | Всегда находится на нижнем уровне |
| **Двумерная структура данных** | Требует двух и более указателей связи на узел — это про деревья |

> Ключевое различение: **дерево без корня даёт ЛЕС, а не поддерево.** Убрав корень,
> мы получаем несколько несвязанных между собой поддеревьев, а их совокупность
> и называется лесом. Это самая частая ошибка в этой теме.

## Терминология

- **Корень** — узел без родителя.
- **Лист** — узел без потомков.
- **Высота узла** — длина самого длинного пути до листа.
- **Глубина узла** — длина пути от корня.
- **Высота дерева** = высота корня.

**Двоичное дерево** — у каждого узла не более двух потомков.

| Вид | Свойство |
|---|---|
| **Полное (full)** | У каждого узла 0 или 2 потомка |
| **Совершенное (perfect)** | Все уровни заполнены полностью |
| **Почти полное (complete)** | Все уровни, кроме последнего, заполнены; последний заполняется слева направо |
| **Вырожденное** | У каждого узла один потомок — фактически список |

Совершенное дерево высоты h содержит 2^(h+1) − 1 узлов; дерево из n узлов имеет высоту не менее ⌊log₂ n⌋.

## Двоичное дерево поиска (BST)

**Определяющее свойство:** для каждого узла все ключи в **левом** поддереве **меньше** ключа узла, а в **правом** — **больше**. Свойство должно выполняться не только для непосредственных детей, но и для всего поддерева целиком — это частая ловушка в заданиях. Именно оно позволяет искать как двоичным поиском: сравнили с узлом и отбросили половину дерева.

**Поиск числа 4 — сравнение отбрасывает поддерево целиком:**

```
                 (8)
                /   \
             (3)     10        4 < 8 → идём влево,
             / \       \       всё правое поддерево отброшено
            1  (6)      14
               /  \     /
              4    7  13

        шаг 1:  4 < 8   →  влево
        шаг 2:  4 > 3   →  вправо
        шаг 3:  4 < 6   →  влево
        шаг 4:  4 = 4   →  нашли

        4 сравнения на 9 узлов
```

**Почему высота решает всё:**

```
    сбалансированное (h ≈ log n)      вырожденное (h = n)
    ────────────────────────────      ───────────────────
              (4)                      (1)
             /   \                        \
          (2)     (6)                      (2)
          / \     / \                        \
         1   3   5   7                        (3)
                                                \
                                                 (4) ...
    h = 3, поиск ≤ 3 сравнений        h = n, поиск до n сравнений
           O(log n)                          O(n) — как список
```

```c
typedef struct Node {
    int key;
    struct Node *left, *right;
} Node;

Node* search(Node *root, int key) {
    while (root && root->key != key)
        root = (key < root->key) ? root->left : root->right;
    return root;
}

Node* insert(Node *root, int key) {
    if (!root) {
        Node *n = malloc(sizeof(Node));
        n->key = key; n->left = n->right = NULL;
        return n;
    }
    if      (key < root->key) root->left  = insert(root->left,  key);
    else if (key > root->key) root->right = insert(root->right, key);
    return root;
}
```

**Сложность:** поиск, вставка и удаление — **O(h)**, где h — высота.

- сбалансированное дерево: h ≈ log n → **O(log n)**;
- вырожденное дерево: h = n → **O(n)**.

> **Худший случай возникает при вставке уже отсортированных ключей**: дерево превращается в связный список. Ради защиты от этого и придуманы самобалансирующиеся деревья.

### Удаление из BST — три случая

1. **Лист** — просто удалить.
2. **Один потомок** — заменить узел его потомком.
3. **Два потомка** — заменить ключ узла на **преемника** (минимум правого поддерева) или **предшественника** (максимум левого), затем удалить тот узел.

## Обходы дерева

Все три обхода делают одно и то же — заходят в левое поддерево, в правое и посещают сам узел, — и различаются **только тем, в какой момент посещается узел**: до спуска, между спусками или после. Отсюда и названия: «пре» — узел первым, «ин» — узел в середине, «пост» — узел последним. Запомнив это, порядок обхода можно вывести, а не заучивать.

```
    порядок трёх действий:  [узел]  [левое]  [правое]

    pre-order:   узел → левое → правое     У Л П
    in-order:    левое → узел → правое     Л У П
    post-order:  левое → правое → узел     Л П У
                          ↑
                   меняется только позиция «У»
```

```c
void preorder(Node *n)  { if (!n) return; visit(n); preorder(n->left);  preorder(n->right); }
void inorder(Node *n)   { if (!n) return; inorder(n->left);  visit(n); inorder(n->right); }
void postorder(Node *n) { if (!n) return; postorder(n->left); postorder(n->right); visit(n); }
```

**Сложность.** Любой обход посещает каждый узел ровно один раз — **O(n)** по времени. Память — **O(h)** на стек рекурсии: у сбалансированного дерева это O(log n), у вырожденного O(n). Обход в ширину требует **O(n)** памяти на очередь.

| Обход | Порядок | Применение |
|---|---|---|
| **Прямой (pre-order)** | Узел → левое → правое | Копирование дерева, префиксная запись |
| **Симметричный (in-order)** | Левое → **узел** → правое | **Для BST даёт отсортированную последовательность** |
| **Обратный (post-order)** | Левое → правое → узел | Удаление дерева, постфиксная запись |
| **В ширину (по уровням)** | Уровень за уровнем | Обход с очередью |

**Пример.** Дерево:

```
      5
     / \
    3   8
   / \
  1   4
```

- pre-order: 5 3 1 4 8
- **in-order: 1 3 4 5 8** ← отсортировано
- post-order: 1 4 3 8 5
- по уровням: 5 3 8 1 4

## Сбалансированные деревья

### AVL-дерево

**Условие балансировки:** для **любого** узла высоты левого и правого поддеревьев различаются не более чем на 1.

Баланс-фактор = высота(левое) − высота(правое) ∈ {−1, 0, 1}. При нарушении выполняются **повороты**:

| Случай | Исправление |
|---|---|
| Left-Left | Правый поворот |
| Right-Right | Левый поворот |
| Left-Right | Левый поворот потомка, затем правый |
| Right-Left | Правый поворот потомка, затем левый |

Гарантирует высоту ≈ 1,44·log₂ n. Строже сбалансировано, чем красно-чёрное, — быстрее поиск, но дороже вставка/удаление.

### Красно-чёрное дерево

Каждый узел окрашен в красный или чёрный. Свойства:

1. Корень чёрный.
2. Все листья (NIL) чёрные.
3. **У красного узла оба потомка чёрные** (нет двух красных подряд).
4. На всех путях от узла до листьев одинаковое число чёрных узлов.

Гарантирует высоту ≤ 2·log₂(n+1). Балансировка дешевле, чем у AVL, поэтому применяется в `std::map`, `TreeMap` в Java, планировщике Linux.

| | AVL | Красно-чёрное |
|---|---|---|
| Балансировка | Строже | Слабее |
| Поиск | Быстрее | Чуть медленнее |
| Вставка/удаление | Дороже | Дешевле |
| Применение | Много чтений | Смешанная нагрузка |

### Многопутевые деревья: 2-3, 2-3-4, B-деревья

В многопутевом дереве узел хранит **несколько элементов данных и несколько указателей связи**.

**2-3-4-дерево.** Название говорит, сколько потомков может быть у узла: 2, 3 или 4.

| Тип узла | Элементов данных | Связей (если не лист) |
|---|---|---|
| 2-узел | 1 | **2** |
| 3-узел | 2 | **3** |
| 4-узел | 3 | **4** |

Свойства:

- элементы внутри узла **упорядочены по возрастанию ключа**;
- у узла с ключами k₀, k₁, k₂ ровно четыре поддерева: с ключами меньше k₀; между k₀ и k₁; между k₁ и k₂; больше k₂;
- **все листья на одном уровне** — дерево идеально сбалансировано по построению;
- баланс поддерживается **самобалансировкой при вставке**: переполненный узел разбивается.

**Разбиение узла.** Когда при спуске встречается заполненный 4-узел, он разбивается:
средний элемент поднимается в родителя, а два оставшихся расходятся в два узла-«брата».
Если разбивается корень, создаётся новый корневой узел, и высота дерева растёт **вверх** —
поэтому все листья и остаются на одном уровне.

**B-дерево** — обобщение на произвольный порядок: узел может хранить сотни ключей.
Предложено Байером и Мак-Крейтом в **1972 году**. Смысл — минимизировать число обращений
к **диску**: одно чтение приносит целый узел с сотнями ключей, и дерево из миллионов
записей имеет высоту 3–4. Это основа индексов почти всех СУБД и файловых систем.

**B+-дерево** — вариант, где данные хранятся только в листьях, а листья связаны в список.
Позволяет и точечный поиск, и быстрый перебор диапазона.

> Красно-чёрное дерево — это способ представить 2-3-4-дерево обычным двоичным:
> 3- и 4-узлы моделируются красными связями. Отсюда и правило «нет двух красных подряд».

### Дерево выражений

Арифметическое выражение в виде дерева: операции во внутренних узлах, операнды в листьях.

```
Выражение (3 + 5) * 2:
        *
       / \
      +   2
     / \
    3   5
```

| Обход | Результат | Как называется |
|---|---|---|
| pre-order | `* + 3 5 2` | Префиксная (польская) запись |
| in-order | `3 + 5 * 2` | Инфиксная (нужны скобки) |
| **post-order** | `3 5 + 2 *` | **Постфиксная (обратная польская)** |

Постфиксная запись вычисляется стеком за один проход и не требует скобок — поэтому
именно её используют компиляторы и калькуляторы.

### Дерево Хаффмана

Строится для **сжатия данных**: частым символам достаются короткие двоичные коды,
редким — длинные. Предложено Дэвидом Хаффманом в 1952 году.

Алгоритм построения:

1. Для каждого символа создать узел с весом, равным частоте.
2. Пока узлов больше одного: взять два узла с наименьшими весами, объединить их
   в новый узел с суммарным весом.
3. Путь от корня к листу и есть код символа: влево — 0, вправо — 1.

Код называют **префиксным**: ни один код не является началом другого, поэтому
последовательность декодируется однозначно без разделителей.

### Другие виды деревьев

- **Дерево двоичного поиска (BST)** — база всего семейства.
- **Splay-дерево** — при обращении перемещает найденный узел в корень; хорошо для повторяющихся запросов.
- **Trie (префиксное дерево)** — хранит строки, путь от корня задаёт префикс. Поиск за длину слова, независимо от числа слов.
- **Дерево отрезков, дерево Фенвика** — для запросов на диапазонах.
- **Куча** — не дерево поиска, а дерево с частичным порядком (см. ниже).

## Подобные и эквивалентные деревья

- **Подобные** — совпадает СТРУКТУРА (форма дерева).
- **Эквивалентные** — совпадает и структура, и хранимая в узлах ИНФОРМАЦИЯ.

Эквивалентность — более сильное условие: эквивалентные деревья обязательно подобны,
обратное неверно.

## Двоичная куча

**Почти полное** двоичное дерево со свойством кучи:

- **max-куча**: ключ родителя ≥ ключей потомков (максимум в корне);
- **min-куча**: ключ родителя ≤ ключей потомков (минимум в корне).

> Куча **не** является деревом поиска: между левым и правым потомком порядка нет, поэтому in-order не даёт сортированную последовательность.

### Хранение в массиве

Благодаря «почти полноте» куча укладывается в массив без указателей. **При индексации с нуля:**

| Отношение | Формула |
|---|---|
| Левый потомок узла i | **2i + 1** |
| Правый потомок узла i | **2i + 2** |
| Родитель узла i | **(i − 1) / 2** |

При индексации с единицы: потомки 2i и 2i+1, родитель i/2. Формулу спрашивают часто — уточняйте, с какого индекса нумерация.

**Дерево и массив — это одно и то же:**

```
              (50) 0
             /      \
        (30) 1      (40) 2
        /    \       /
    (10) 3 (20) 4 (35) 5

    индекс:   0     1     2     3     4     5
            ┌────┬────┬────┬────┬────┬────┐
            │ 50 │ 30 │ 40 │ 10 │ 20 │ 35 │
            └────┴────┴────┴────┴────┴────┘

    потомки узла 1 (значение 30):  2·1+1 = 3 → 10
                                   2·1+2 = 4 → 20
    родитель узла 5 (значение 35): (5−1)/2 = 2 → 40   ✓ сходится
```

**Вставка: новый элемент всплывает наверх (просеивание вверх)**

```
    вставляем 45 в конец (индекс 6), родитель = (6−1)/2 = 2 → 40

              (50)                    (50)                  (50)
             /    \                  /    \                /    \
          (30)    (40)     →      (30)    (45)    →     (30)    (45)
          /  \    /  \            /  \    /  \          /  \    /  \
        10   20  35  [45]       10   20  35  40       10   20  35  40

        45 > 40 → меняем       45 < 50 → стоп        куча восстановлена

    поднялись на 1 уровень; в худшем случае — на всю высоту = log n
```

**Извлечение максимума: корень уходит, последний встаёт на его место и тонет**

```
              (50)  ← забираем              (35)                  (40)
             /    \                        /    \                /    \
          (30)    (40)        →         (30)    (40)    →     (30)    (35)
          /  \    /                     /  \    /             /  \    /
        10   20  35                   10   20  ✕            10   20

    последний (35) → в корень      35 < 40 → меняем      куча восстановлена
```

**Сложность.** Вставка и извлечение максимума — **O(log n)**, потому что элемент проходит не больше высоты дерева, а высота почти полного дерева равна ⌊log₂ n⌋. Просмотр максимума — **O(1)** (он всегда в корне). Построение кучи из готового массива — **O(n)**, а не O(n log n): большинство узлов сидит у самого низа и тонуть им почти некуда. Память — **O(1)**, куча живёт прямо в массиве.

> Куча **не** упорядочена целиком: она гарантирует только «родитель ≥ потомков».
> Поиск произвольного элемента в ней — O(n), и это отличает её от BST.

### Операции

```c
// Просеивание вниз — O(log n)
void heapify(int *a, int n, int i) {
    int largest = i, l = 2*i + 1, r = 2*i + 2;
    if (l < n && a[l] > a[largest]) largest = l;
    if (r < n && a[r] > a[largest]) largest = r;
    if (largest != i) {
        int t = a[i]; a[i] = a[largest]; a[largest] = t;
        heapify(a, n, largest);
    }
}

// Вставка — O(log n): в конец, затем просеивание вверх
void push(int *a, int *n, int v) {
    int i = (*n)++;
    a[i] = v;
    while (i > 0 && a[(i-1)/2] < a[i]) {
        int p = (i-1)/2;
        int t = a[i]; a[i] = a[p]; a[p] = t;
        i = p;
    }
}

// Извлечение максимума — O(log n)
int pop_max(int *a, int *n) {
    int top = a[0];
    a[0] = a[--(*n)];
    heapify(a, *n, 0);
    return top;
}
```

| Операция | Сложность |
|---|---|
| Найти максимум (min) | **O(1)** |
| **Извлечь** максимум | **O(log n)** |
| Вставить | O(log n) |
| Построить кучу из массива | **O(n)** |
| Сортировка кучей | O(n log n) |

Обратите внимание на разницу: **посмотреть** корень — O(1), а **извлечь** — O(log n), потому что после удаления надо восстановить свойство кучи.

Построение кучи «снизу вверх» стоит O(n), а не O(n log n) — нижние уровни просеиваются недалеко.

## Сравнение структур

| | BST (сбаланс.) | Хеш-таблица | Куча |
|---|---|---|---|
| Поиск по ключу | O(log n) | **O(1)** | O(n) |
| Минимум / максимум | O(log n) | O(n) | **O(1)** |
| Обход по порядку | **Да** | Нет | Нет |
| Диапазонный запрос | **Да** | Нет | Нет |

## Быстрая проверка себя

1. Какой обход BST даёт отсортированную последовательность? *(in-order)*
2. Какова сложность поиска в вырожденном BST? *(O(n))*
3. Условие балансировки AVL-дерева? *(разница высот поддеревьев ≤ 1)*
4. Формула родителя в куче при индексации с нуля? *((i−1)/2)*
5. Сложность извлечения максимума из кучи? *(O(log n))*
