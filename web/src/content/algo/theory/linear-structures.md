## Определения, которые спрашивают дословно

| Термин | Формулировка в тесте |
|---|---|
| **Стек** | Линейный список, в котором все операции вставки и удаления выполняются только с одного конца списка — **вершины**. Принцип **LIFO** |
| **Очередь** | Добавление с одного конца, извлечение с другого. Принцип **FIFO** |
| **Дек (двусторонняя очередь)** | Линейный список, в котором все операции вставки и удаления выполняются **на обоих концах** списка |
| **Связный список** | Линейный набор объектов класса **с самоадресацией** (узел содержит указатель на такой же узел) |
| **Заголовок списка** | Его наличие позволяет избежать **опустошения списка** |
| **Вставка в неупорядоченный массив** | Выполняется за **постоянное время** независимо от количества элементов |

> Различайте три формулировки, которые звучат почти одинаково:
> «только с одного конца — вершины» → **стек**;
> «на обоих концах» → **дек**;
> «с одного конца добавление, с другого извлечение» → **очередь**.

## Сводная таблица сложностей

| Операция | Массив | Динамический массив | Односвязный список | Двусвязный список |
|---|---|---|---|---|
| Доступ по индексу | **O(1)** | **O(1)** | O(n) | O(n) |
| Поиск значения | O(n) | O(n) | O(n) | O(n) |
| Вставка в начало | O(n) | O(n) | **O(1)** | **O(1)** |
| Вставка в конец | O(1)¹ | O(1) аморт. | O(n) или O(1)² | **O(1)**² |
| Вставка по известному узлу | O(n) | O(n) | O(1)³ | **O(1)** |
| Удаление по известному узлу | O(n) | O(n) | **O(n)**⁴ | **O(1)** |
| Дополнительная память | Нет | Нет | Указатель на элемент | Два указателя |

¹ если есть место. ² при хранении указателя на хвост. ³ вставка **после** узла. ⁴ нужен предыдущий узел.

**Главный контраст:** массив даёт быстрый доступ по индексу, но дорогую вставку в начало. Список — наоборот.

## Массив

Непрерывный участок памяти, где элементы лежат подряд, один за другим. Именно из-за непрерывности адрес любого элемента вычисляется одной арифметической операцией — `база + индекс × размер_элемента`, — и процессору не нужно никуда ходить по ссылкам. Отсюда доступ за **O(1)** к любому элементу независимо от того, первый он или миллионный.

```
    база = 1000, размер элемента = 4 байта

    индекс:      0      1      2      3      4
              ┌──────┬──────┬──────┬──────┬──────┐
    память:   │  17  │  42  │   8  │  95  │  23  │
              └──────┴──────┴──────┴──────┴──────┘
    адрес:     1000   1004   1008   1012   1016
                                ↑
                a[2] = 1000 + 2×4 = 1008   → сразу, без перебора
```

**Вставка в середину требует сдвига** — вот почему она O(n):

```
    вставляем 50 в позицию 1:

    было:   [ 17 │ 42 │  8 │ 95 │ 23 │    ]
                   └────┴────┴────┴────┘
                    все едут вправо на 1

    стало:  [ 17 │ 50 │ 42 │  8 │ 95 │ 23 ]
                   ↑ новый

    сдвинуто 4 элемента; в худшем случае (вставка в начало) — все n
```

**Плюсы:** O(1) доступ, отличная локальность (кеш процессора подтягивает соседние элементы заранее, и обход массива идёт в разы быстрее обхода списка), нет накладных расходов на указатели.

**Минусы:** фиксированный размер, вставка и удаление в середине требуют сдвига — **O(n)**.

**Динамический массив** (`std::vector`, `ArrayList`) при заполнении выделяет вдвое больший блок и копирует туда данные. Отдельная такая вставка стоит O(n), но происходит редко: между удвоениями идут дешёвые вставки за O(1). Если размазать стоимость копирования по всем вставкам, получится **амортизированная O(1)**.

```
    вместимость:  1 → 2 → 4 → 8 → 16 → 32 ...
    копирований:  1   2   4   8   16        всего ≈ 2n на n вставок
                                            → в среднем 2 операции на вставку
```

## Односвязный список

Элементы больше не лежат подряд: каждый узел хранит своё значение и **указатель на следующий** узел, а сами узлы разбросаны по памяти как попало. Плата за это — потеря доступа по индексу: чтобы добраться до k-го элемента, надо пройти по цепочке от головы, то есть **O(n)**. Выигрыш — вставка и удаление в начале за **O(1)**: достаточно переставить пару указателей, ничего не сдвигая.

```
    head
     │
     ▼
    ┌────┬───┐   ┌────┬───┐   ┌────┬───┐   ┌────┬───┐
    │ 17 │ ●─┼──▶│ 42 │ ●─┼──▶│  8 │ ●─┼──▶│ 95 │ ✕ │
    └────┴───┘   └────┴───┘   └────┴───┘   └────┴───┘
     данные next                                 NULL
```

**Вставка в начало — переставили два указателя:**

```
    было:   head ──▶ [17] ──▶ [42] ──▶ ...

    новый узел [50] смотрит на старую голову:
            [50] ──▶ [17] ──▶ [42] ──▶ ...
    head перевесили на [50]:
    стало:  head ──▶ [50] ──▶ [17] ──▶ [42] ──▶ ...

    ни один элемент не сдвинулся  →  O(1)
```

**Почему удаление стоит O(n).** Чтобы выкинуть узел, нужно изменить указатель у **предыдущего**, а односвязный список назад ходить не умеет — предыдущий приходится искать с головы.

```
    удаляем [8]:   [42] ──▶ [8] ──▶ [95]
                     │               ▲
                     └───────────────┘   next предыдущего в обход удаляемого

    сам обход указателей — O(1), но поиск предыдущего — O(n)
```

```c
typedef struct Node {
    int data;
    struct Node *next;
} Node;
```

```c
// Вставка в начало — O(1)
Node *push_front(Node *head, int v) {
    Node *n = malloc(sizeof(Node));
    n->data = v;
    n->next = head;
    return n;                    // новая голова
}

// Обход — O(n)
for (Node *p = head; p != NULL; p = p->next)
    printf("%d ", p->data);

// Удаление узла по значению — O(n), нужен предыдущий
Node *remove_value(Node *head, int v) {
    Node dummy = { .next = head };     // фиктивный узел упрощает крайние случаи
    Node *prev = &dummy;
    while (prev->next && prev->next->data != v) prev = prev->next;
    if (prev->next) {
        Node *dead = prev->next;
        prev->next = dead->next;
        free(dead);
    }
    return dummy.next;
}

// Разворот списка — O(n), O(1) памяти
Node *reverse(Node *head) {
    Node *prev = NULL;
    while (head) {
        Node *next = head->next;
        head->next = prev;
        prev = head;
        head = next;
    }
    return prev;
}
```

**Ключевой момент для теста:** даже имея указатель **на сам удаляемый узел**, в односвязном списке удаление стоит O(n) — предшественника приходится искать с начала.

## Двусвязный список

```c
typedef struct DNode {
    int data;
    struct DNode *prev, *next;
} DNode;
```

```c
// Удаление узла по указателю — O(1)
void erase(DNode *n) {
    if (n->prev) n->prev->next = n->next;
    if (n->next) n->next->prev = n->prev;
    free(n);
}
```

Узел знает своего предшественника, поэтому связи перестраиваются сразу. Плата — дополнительный указатель на элемент.

Двусвязный список позволяет обход в обе стороны и лежит в основе `std::list`, `LinkedList` в Java, deque во многих реализациях.

**Кольцевой список:** `next` последнего указывает на первый (а `prev` первого — на последний). Удобен для циклических обходов.

## Стек — LIFO

Последним пришёл — первым вышел (Last In — First Out). Добавление и извлечение выполняются **только с одного конца**, который называется вершиной; до элементов в глубине добраться нельзя, пока не снимешь всё, что лежит выше. Работает как стопка тарелок: кладёшь сверху и берёшь сверху.

```
        push(3)              pop() → 3
           │                     ▲
           ▼                     │
        ┌─────┐               ┌─────┐
   top ▶│  3  │          top ▶│  3  │ ──── снимается
        ├─────┤               ├─────┤
        │  2  │               │  2  │ ◀── станет вершиной
        ├─────┤               ├─────┤
        │  1  │               │  1  │
        └─────┘               └─────┘
         дно                   дно

    доступен только верхний элемент
```

**Сложность.** `push`, `pop`, `peek`, проверка на пустоту — все по **O(1)**: работа идёт с одним индексом вершины, никаких сдвигов и обходов. Поиск элемента в стеке — O(n), но это уже не операция стека.

```c
typedef struct { int data[MAX]; int top; } Stack;

void init(Stack *s)          { s->top = -1; }
int  is_empty(Stack *s)      { return s->top < 0; }
void push(Stack *s, int v)   { s->data[++s->top] = v; }   // O(1)
int  pop(Stack *s)           { return s->data[s->top--]; } // O(1)
int  peek(Stack *s)          { return s->data[s->top]; }
```

**Разбор задания.** `push(1); push(2); push(3); pop(); push(4); pop();`

```
push(1) → [1]
push(2) → [1, 2]
push(3) → [1, 2, 3]
pop()   → [1, 2]        снят 3
push(4) → [1, 2, 4]
pop()   → [1, 2]        снят 4
```

На вершине остаётся **2**.

**Применения стека:**

- проверка правильности расстановки скобок;
- вычисление выражений в обратной польской записи;
- преобразование инфиксной записи в постфиксную (алгоритм сортировочной станции);
- стек вызовов функций;
- итеративный обход в глубину;
- отмена действий (undo).

```c
// Проверка скобок
int balanced(const char *s) {
    Stack st; init(&st);
    for (int i = 0; s[i]; i++) {
        if (strchr("([{", s[i])) push(&st, s[i]);
        else if (strchr(")]}", s[i])) {
            if (is_empty(&st)) return 0;
            char open = pop(&st);
            if ((s[i] == ')' && open != '(') ||
                (s[i] == ']' && open != '[') ||
                (s[i] == '}' && open != '{')) return 0;
        }
    }
    return is_empty(&st);
}
```

## Очередь — FIFO

Первым пришёл — первым вышел (First In — First Out). В отличие от стека, здесь **два разных конца**: добавляют в хвост, извлекают из головы. Ровно как живая очередь в кассу — кто встал раньше, тот и уйдёт раньше.

```
    enqueue(4) ──▶ ┌───┬───┬───┬───┐ ──▶ dequeue() → 1
                   │ 4 │ 3 │ 2 │ 1 │
                   └───┴───┴───┴───┘
                  tail            head
                 (хвост)         (голова)

    добавляем сюда          забираем отсюда
```

Наивная реализация на массиве плоха: после извлечения приходится либо сдвигать все элементы (**O(n)** на каждое извлечение), либо голова уползает вправо, и начало массива простаивает, хотя место там свободно.

**Решение — кольцевой (циклический) буфер.** Индексы головы и хвоста при достижении конца массива заворачиваются в начало через остаток от деления, и освободившиеся ячейки переиспользуются:

```
    MAX = 6, head=4, tail=1  (очередь: 40, 50, 10)

         0     1     2     3     4     5
      ┌─────┬─────┬─────┬─────┬─────┬─────┐
      │ 10  │     │     │     │ 40  │ 50  │
      └─────┴─────┴─────┴─────┴─────┴─────┘
         ▲     ▲                 ▲
       конец  tail             head
       данных                  начало данных

      enqueue(20):  data[1]=20, tail = (1+1) % 6 = 2
      dequeue():    вернёт 40,  head = (4+1) % 6 = 5

      хвост «перепрыгнул» через границу массива и пошёл по кругу
```

```c
typedef struct { int data[MAX]; int head, tail, size; } Queue;

void enqueue(Queue *q, int v) {
    q->data[q->tail] = v;
    q->tail = (q->tail + 1) % MAX;      // ← закольцовывание
    q->size++;
}

int dequeue(Queue *q) {
    int v = q->data[q->head];
    q->head = (q->head + 1) % MAX;
    q->size--;
    return v;
}
```

Обе операции — **O(1)**, освободившиеся ячейки переиспользуются.

**Применения:** обход в ширину (BFS), очереди задач и сообщений, буферизация ввода-вывода, планировщики.

**Дек (deque)** — двусторонняя очередь: добавление и извлечение с обоих концов за O(1).

## Приоритетная очередь

Извлекается не самый ранний, а элемент с наибольшим (или наименьшим) приоритетом.

| Реализация | Вставка | Извлечение максимума |
|---|---|---|
| Неотсортированный массив | O(1) | O(n) |
| Отсортированный массив | O(n) | O(1) |
| **Двоичная куча** | **O(log n)** | **O(log n)** |

Куча — стандартная реализация; на ней построен алгоритм Дейкстры.

## Массивы подробнее

**Неупорядоченный массив.** Вставка — в первую свободную ячейку, **O(1)**: искать место
не нужно. Поиск — перебор, O(n). Удаление — найти O(n) плюс сдвиг O(n).

**Упорядоченный массив.** Вставка O(n): надо найти место и сдвинуть хвост. Зато поиск
двоичный — **O(log n)**.

| Операция | Неупорядоченный | Упорядоченный |
|---|---|---|
| Вставка | **O(1)** | O(n) |
| Поиск | O(n) | **O(log n)** |
| Удаление | O(n) | O(n) |

> Отсюда правило выбора: много вставок и мало поисков — неупорядоченный;
> много поисков и мало вставок — упорядоченный.

**Дубликаты.** Если ключи обязаны быть уникальными, каждая вставка требует проверки
всего массива — вставка деградирует до O(n). Если дубликаты разрешены, поиск должен
продолжаться и после первого совпадения, а удаление всех вхождений требует просмотра
всех n ячеек.

**Двумерные массивы** хранятся построчно (row-major): сначала вся строка 0, потом строка 1.
Обход по строкам поэтому быстрее обхода по столбцам — данные лежат подряд и попадают
в кеш процессора.

**Динамический массив** при заполнении выделяет вдвое больший блок и копирует данные.
Отдельная такая вставка стоит O(n), но благодаря удвоению **амортизированная** сложность — O(1).

## Списки подробнее

**Односвязный список.** Узел хранит данные и один указатель — на следующий узел.
Последний указывает на «пусто». Есть указатель на голову; часто добавляют и указатель
на хвост, чтобы вставка в конец стала O(1).

**Двусвязный список.** Два указателя связи: на следующий и на предыдущий. Позволяет
обход в обе стороны и удаление узла по указателю за O(1).

**Кольцевой список.** Последний узел ссылается на первый. Удобен для циклических
обходов (планировщик задач, игра «считалочка»).

**Список с заголовком.** Фиктивный первый узел, не хранящий полезных данных.
Он есть всегда, поэтому список формально никогда не пуст — исчезают особые случаи
«вставка в пустой список» и «удаление первого элемента», код становится единообразным.

**Итератор** — объект, хранящий текущую позицию в списке. Позволяет нескольким
независимым обходам идти одновременно, чего не даёт единственное поле `current`
внутри самого списка.

**Список с пропусками (skip list)** — многоуровневый список, где верхние уровни
«перепрыгивают» через элементы. Даёт поиск за O(log n) без деревьев.

## Стек подробнее

**Операции:** `push` (положить), `pop` (снять), `peek`/`top` (посмотреть вершину
не снимая), `isEmpty`, `isFull`. Все — **O(1)**.

**Реализации:** на массиве (быстро, но размер ограничен) и на связном списке
(размер не ограничен, но накладные расходы на узлы).

**Применения:**

- проверка правильности расстановки скобок;
- вычисление постфиксной (обратной польской) записи;
- преобразование инфиксной записи в постфиксную — алгоритм сортировочной станции;
- стек вызовов функций и реализация рекурсии;
- итеративный обход в глубину;
- отмена действий (undo), история переходов в браузере.

### Инфиксная, префиксная, постфиксная запись

| Запись | Пример | Кто использует |
|---|---|---|
| Инфиксная | `A + B * C` | Человек |
| Префиксная (польская) | `+ A * B C` | Некоторые языки (Lisp) |
| Постфиксная (обратная польская) | `A B C * +` | Компиляторы, калькуляторы |

Постфиксная запись не требует скобок и приоритетов, а вычисляется стеком за один проход:
число — кладём в стек; операция — снимаем два операнда, применяем, результат кладём обратно.
Именно поэтому компьютеру удобнее она, а не привычная человеку инфиксная.

## Очередь подробнее

**Операции:** `enqueue` (добавить в хвост), `dequeue` (извлечь из головы), `front`, `rear`.

**Кольцевой буфер** — обязательный приём для реализации на массиве: индексы головы
и хвоста при достижении конца массива переходят в начало через остаток от деления.
Без этого либо голова уползает вправо и начало массива простаивает, либо каждое
извлечение требует сдвига всех элементов за O(n).

**Различение полной и пустой очереди.** Когда голова и хвост совпадают, очередь может
быть и пустой, и полной. Решают либо счётчиком элементов, либо оставляя одну ячейку
всегда свободной.

**Дек (двусторонняя очередь)** допускает добавление и извлечение с обоих концов.
Дек — обобщение: ограничив его одним концом, получаем стек; ограничив добавление
одним концом, а извлечение другим — обычную очередь.

**Приоритетная очередь** извлекает не самый ранний элемент, а элемент с наибольшим
(или наименьшим) приоритетом.

| Реализация | Вставка | Извлечение приоритетного |
|---|---|---|
| Неотсортированный массив | O(1) | O(n) |
| Отсортированный массив | O(n) | O(1) |
| **Двоичная куча** | **O(log n)** | **O(log n)** |

Куча — стандартная реализация; на ней построен алгоритм Дейкстры.

## Что выбрать

| Задача | Структура |
|---|---|
| Частый доступ по индексу | Массив |
| Много вставок, мало поиска | Неупорядоченный массив или список |
| Много поиска, мало вставок | Упорядоченный массив |
| Частые вставки/удаления в начале | Список |
| Отмена действий, скобки, DFS, постфиксная запись | Стек |
| Обработка в порядке поступления, BFS, буферизация | Очередь |
| Операции с обоих концов | Дек |
| Всегда нужен минимум/максимум | Приоритетная очередь (куча) |
| Обход в обе стороны, удаление по ссылке | Двусвязный список |
| Циклический обход | Кольцевой список |

## Быстрая проверка себя

1. Сложность вставки в начало односвязного списка? *(O(1))*
2. Сложность доступа к k-му элементу списка? *(O(n))*
3. В каком списке удаление узла по указателю стоит O(1)? *(в двусвязном)*
4. Зачем очередь на массиве делают кольцевой? *(чтобы избежать сдвигов и переиспользовать ячейки)*
5. Какой принцип у стека? *(LIFO)*
