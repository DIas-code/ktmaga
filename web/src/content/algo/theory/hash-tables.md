## Терминология теста

Задания этой темы почти всегда — определения. Обратите внимание: на КТ говорят
**«пробирование»**, а не «зондирование».

| Термин в тесте | Определение, по которому узнаётся |
|---|---|
| **Хеширование** | Общее название популярного класса методов поиска |
| **Хеш-адрес** | То, что вычисляется по ключу и используется для поиска (НЕ адрес переменной в памяти) |
| **Коэффициент заполнения** | Отношение количества элементов данных в хеш-таблице к размеру массива |
| **Линейное пробирование** | Проверяются ячейки, соседние с исходной позицией |
| **Квадратичное пробирование** | Ищутся пустые ячейки на бо́льших расстояниях вместо соседних |
| **Двойное хеширование** | Используются ДВЕ хеш-функции для построения последовательности проб |
| **Метод цепочек** | В ячейке хранится список всех элементов с этим индексом |
| **Открытая адресация** | Общее название для трёх схем: линейное и квадратичное пробирование, двойное хеширование |

> Три разновидности открытой адресации надо помнить дословно: **линейное пробирование,
> квадратичное пробирование и двойное хеширование**. В вариантах ответа подсовывают
> «симметричное пробирование», «полиноминальное пробирование», «тройное хеширование» —
> ничего этого не существует.

## Идея

Хеш-таблица хранит пары «ключ — значение» в массиве, но позицию не ищет, а **вычисляет** из самого ключа с помощью хеш-функции. В этом весь фокус: массиву всё равно, что лежит в ячейке, — если мы умеем по ключу мгновенно получить индекс, то и добраться до значения сможем за одно обращение, не сравнивая ключ ни с чем.

```
индекс = h(ключ) mod m        // m — размер таблицы
```

**Как ключи раскладываются по ячейкам** (m = 7, h — сумма кодов букв):

```
    "кот"  → h = 1042 → 1042 mod 7 = 6
    "дом"  → h =  978 →  978 mod 7 = 5
    "сад"  → h = 1015 → 1015 mod 7 = 0

        0      1      2      3      4      5      6
      ┌──────┬──────┬──────┬──────┬──────┬──────┬──────┐
      │ сад  │      │      │      │      │ дом  │ кот  │
      └──────┴──────┴──────┴──────┴──────┴──────┴──────┘

    поиск "дом": считаем h → 5 → сразу смотрим в ячейку 5
                 ни одного сравнения с другими ключами
```

Это позволяет находить элемент **за O(1) в среднем** — без перебора и без сравнения ключей по порядку. Сравните: в массиве поиск O(n), в дереве O(log n), здесь — константа, не зависящая от размера таблицы.

## Производительность

| Операция | Средний случай | Худший случай |
|---|---|---|
| Вставка | **O(1)** | O(n) |
| Поиск | **O(1)** | O(n) |
| Удаление | **O(1)** | O(n) |

Худший случай наступает, когда все ключи попадают в одну корзину — тогда структура вырождается в список.

**Чего хеш-таблица НЕ умеет:**

- обход в отсортированном порядке;
- поиск минимума/максимума за O(1);
- поиск по диапазону («все ключи от 10 до 20»).

Для этого нужны деревья поиска.

## Коллизии

**Коллизия** — ситуация, когда разные ключи дают один и тот же индекс.

Коллизии **неизбежны**: ключей потенциально больше, чем ячеек (парадокс дней рождения показывает, что при 23 случайных ключах и 365 ячейках вероятность совпадения уже около 50%). Поэтому любая реализация обязана иметь схему разрешения коллизий.

## Дизайн хеш-функции

Хорошая хеш-функция:

1. **Детерминирована** — один ключ всегда даёт один хеш.
2. **Быстро вычисляется** — иначе теряется смысл O(1).
3. **Равномерно распределяет** ключи по диапазону.
4. **Лавинообразна** — изменение одного бита ключа меняет примерно половину битов хеша.

**Метод деления:** `h(k) = k mod m`. Размер m берут **простым** числом, далёким от степеней двойки: при m = 2ᵖ хеш вырождается в младшие p бит ключа.

**Метод умножения:** `h(k) = ⌊m · (k·A mod 1)⌋`, где A ≈ 0,618 (золотое сечение). К размеру таблицы не привередлив.

**Для строк — полиномиальный хеш:**

```c
unsigned long hash_string(const char *s, unsigned long m) {
    unsigned long h = 0;
    while (*s) h = (h * 31 + (unsigned char)*s++) % m;   // 31 — простое
    return h;
}
```

Плохие хеш-функции: сумма кодов символов (анаграммы дают одинаковый хеш), длина строки, первый символ.

## Схемы разрешения коллизий

### 1. Метод цепочек (separate chaining)

В каждой ячейке хранится **связный список** всех элементов с этим индексом.

```
[0] → NULL
[1] → (ключ7) → (ключ22) → NULL
[2] → (ключ13) → NULL
```

**Плюсы:** прост, допускает коэффициент заполнения больше 1, удаление тривиально.
**Минусы:** память на указатели, плохая локальность (список разбросан по памяти).

Средняя длина цепочки равна коэффициенту заполнения α, поэтому поиск — O(1 + α).

### 2. Открытая адресация

Все элементы хранятся **в самом массиве**. При коллизии ищется другая свободная ячейка по некоторой последовательности проб.

Требование: **α < 1** (элементов не больше, чем ячеек).

#### Линейное зондирование

```
h(k, i) = (h(k) + i) mod m,     i = 0, 1, 2, ...
```

Проверяем следующую ячейку, потом ещё следующую — пока не найдём свободную. Идея предельно простая, но именно из-за шага в единицу занятые ячейки начинают слипаться.

**Вставка при коллизии:**

```
    m = 8, вставляем ключ с h(k) = 3, ячейка занята

        0     1     2     3     4     5     6     7
      ┌─────┬─────┬─────┬─────┬─────┬─────┬─────┬─────┐
      │     │     │     │  A  │  B  │  C  │     │     │
      └─────┴─────┴─────┴─────┴─────┴─────┴─────┴─────┘
                          ↑     ↑     ↑     ↑
                        i=0   i=1   i=2   i=3
                       занято занято занято СВОБОДНО → сюда

        просмотрено 4 ячейки вместо одной
```

**Проблема — первичная кластеризация:** занятые ячейки слипаются в длинные группы. Чем длиннее кластер, тем больше у него «площадь захвата»: новый ключ, попавший в любую его ячейку, доедет до конца кластера и удлинит его ещё на единицу. Кластеры растут тем быстрее, чем они больше.

```
    было:   [ ▓ ▓ ▓ ░ ░ ▓ ░ ░ ]     кластер из 3
    любой ключ с h = 0,1,2 или 3 приземлится в позицию 3
    стало:  [ ▓ ▓ ▓ ▓ ░ ▓ ░ ░ ]     кластер из 4, и слился с соседним
```

Плюс — отличная локальность памяти: соседние ячейки уже подтянуты в кеш процессора, поэтому на практике линейное зондирование часто быстрее «умных» схем при небольшом α.

#### Квадратичное зондирование

```
h(k, i) = (h(k) + c₁·i + c₂·i²) mod m
```

Шаг растёт квадратично, поэтому длинные кластеры не образуются. Остаётся **вторичная кластеризация**: ключи с одинаковым начальным индексом идут по одной и той же последовательности.

Ограничение: чтобы обойти хотя бы половину таблицы, m должно быть простым, а α ≤ 0,5.

#### Двойное хеширование

```
h(k, i) = (h₁(k) + i · h₂(k)) mod m
```

**Шаг вычисляется второй хеш-функцией и зависит от ключа.** Поэтому ключи с одинаковым начальным индексом расходятся по разным последовательностям — кластеризации нет ни первичной, ни вторичной.

Требование: `h₂(k)` не должна давать 0 и должна быть взаимно простой с m. Практический приём: m — простое, `h₂(k) = 1 + (k mod (m − 1))`.

Это лучшая по качеству схема открытой адресации; плата — два вычисления хеша и худшая локальность.

### Удаление при открытой адресации

Просто очистить ячейку **нельзя** — это разорвёт цепочку проб, и элементы за ней перестанут находиться. Используют специальный маркер «удалено» (tombstone): поиск через него проходит, а вставка может его занять.

## Коэффициент заполнения

**α = n / m** — отношение числа элементов к размеру таблицы.

| Схема | Среднее число проб при поиске (неудачном) |
|---|---|
| Цепочки | 1 + α |
| Линейное зондирование | ≈ ½(1 + 1/(1−α)²) |
| Двойное хеширование | ≈ 1/(1−α) |

При α → 1 открытая адресация деградирует катастрофически. Формула 1/(1−α) объясняет почему: пока таблица заполнена наполовину, знаменатель ещё велик, но у самого края он стремится к нулю, и число проб взлетает.

```
    α = 0,5   ▓▓▓▓░░░░   проб ≈ 2      ▪▪
    α = 0,7   ▓▓▓▓▓▓░░   проб ≈ 3      ▪▪▪
    α = 0,9   ▓▓▓▓▓▓▓░   проб ≈ 10     ▪▪▪▪▪▪▪▪▪▪
    α = 0,95  ▓▓▓▓▓▓▓▓   проб ≈ 20     ▪▪▪▪▪▪▪▪▪▪▪▪▪▪▪▪▪▪▪▪
    α → 1                проб → ∞

    заполнили на 5% больше — работы стало вдвое больше
```

Практические пороги: **α ≈ 0,7** для открытой адресации, **α ≈ 1–2** для цепочек.

При превышении порога выполняется **рехеширование**: создаётся вдвое большая таблица, все элементы перевставляются с пересчётом хеша. Разовая операция стоит O(n), но амортизированная сложность вставки остаётся O(1).

## Сравнение схем

| | Цепочки | Линейное | Квадратичное | Двойное |
|---|---|---|---|---|
| Допускает α > 1 | **Да** | Нет | Нет | Нет |
| Кластеризация | Нет | Первичная | Вторичная | **Нет** |
| Локальность памяти | Плохая | **Отличная** | Хорошая | Средняя |
| Простота удаления | **Высокая** | Нужны маркеры | Нужны маркеры | Нужны маркеры |
| Доп. память | Указатели | **Нет** | **Нет** | **Нет** |

## Совершенное (идеальное) хеширование

Если набор ключей **известен заранее и не меняется** (статическое множество —
ключевые слова языка, набор команд), хеш-функцию можно подобрать так, чтобы коллизий
не было **вовсе**. Тогда поиск занимает O(1) не в среднем, а **гарантированно,
даже в худшем случае**.

Это единственная схема с такой гарантией — обычное хеширование даёт O(1) лишь в среднем.
Плата: при добавлении нового ключа всю функцию приходится строить заново.

## Удаление и его тонкости

**В методе цепочек** удаление тривиально: узел вынимается из списка.

**При открытой адресации** просто очистить ячейку **нельзя** — это разорвёт цепочку проб,
и элементы, лежащие за ней, перестанут находиться. Используют маркер «удалено»
(tombstone): поиск через него проходит, а вставка может его занять.

Накопление таких маркеров со временем ухудшает поиск, поэтому таблицу периодически
перестраивают.

**При разрешённых дубликатах** удаление всех вхождений ключа требует просмотра всей
последовательности проб до первой пустой ячейки — а это может быть до N ячеек.

## Хеширование на диске

Для внешней памяти таблица разбивается на **блоки**, размер которых совпадает
с размером блока диска. Хеш-функция определяет номер блока, внутри блока идёт
линейный поиск.

**Переполнение блока** — блок заполнен, а в него нужно записать ещё элемент.
Решают либо блоками переполнения (цепочкой), либо расширяемым хешированием.
Если переполнения случаются **редко**, схема с блоками переполнения вполне приемлема;
если часто — производительность падает, и таблицу нужно перестраивать.

Главный критерий эффективности здесь — не число сравнений, а **число обращений к диску**.

## Хеш-таблица против дерева поиска

| | Хеш-таблица | Сбалансированное дерево |
|---|---|---|
| Поиск по ключу | **O(1)** в среднем | O(log n) гарантированно |
| Худший случай | O(n) | **O(log n)** |
| Обход по порядку | **Нет** | Да |
| Диапазонный запрос | **Нет** | Да |
| Минимум / максимум | O(n) | O(log n) |
| Чувствительность к хеш-функции | Высокая | Отсутствует |

Вывод: нужен только доступ по точному ключу — хеш-таблица; нужен порядок,
диапазоны или гарантии худшего случая — дерево.

## Применения

Словари и множества (`unordered_map`, `HashMap`, `dict`), кеши, индексы в БД (hash index), проверка уникальности, подсчёт частот, дедупликация.

## Быстрая проверка себя

1. Какова средняя сложность поиска в хеш-таблице? *(O(1))*
2. Что такое коллизия? *(разные ключи дают одинаковый индекс)*
3. Какой недостаток характерен для линейного зондирования? *(первичная кластеризация)*
4. Чем отличается двойное хеширование? *(шаг задаётся второй хеш-функцией и зависит от ключа)*
5. Что такое коэффициент заполнения? *(α = n/m — число элементов к размеру таблицы)*
