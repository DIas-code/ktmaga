## Определения, которые спрашивают дословно

| Термин | Формулировка в тесте |
|---|---|
| **Общий формат описания функции** | `Тип-возвращаемого-значения имя-функции (список-параметров) { объявления и операторы }` |
| **Определение функции** | Включает **заголовок и тело** функции |
| **Рекурсивный вызов** | Шаг, когда функция вызывает новую копию самой себя, чтобы начать работать над меньшей проблемой |
| **Встраиваемая функция** | Ключевое слово `inline` |
| **Перегрузка функции** | Особенность C++, позволяющая определить несколько функций с одним именем, если они имеют разные наборы параметров |
| **Передача по ссылке** | Функции доступна **сама переменная**, передаваемая в качестве аргумента |
| **Передача по значению** | Функция получает копию, оригинал не меняется |

> Две ловушки этой темы:
> **тип возврата пишется ПЕРЕД именем** функции — вариант «Имя-функции Тип-возвращаемого-значения…»
> выглядит правдоподобно, но неверен;
> **«функции доступна сама переменная» = по ссылке**, а не по значению. По значению
> передаётся копия, и изменения снаружи не видны.

## Зачем нужны функции

- **Повторное использование** — код пишется один раз.
- **Декомпозиция** — большая задача делится на обозримые части.
- **Абстракция** — вызывающему важно, *что* функция делает, а не *как*.
- **Тестируемость** — маленькую функцию легко проверить отдельно.

## Синтаксис объявления

```c
тип_возврата имя(тип1 параметр1, тип2 параметр2) {
    /* тело */
    return значение;
}
```

```c
int square(int x) {
    return x * x;
}

double average(int a, int b) {
    return (a + b) / 2.0;
}
```

**Прототип** объявляет функцию до её определения:

```c
int square(int x);        // прототип (объявление)

int main(void) {
    printf("%d\n", square(5));
    return 0;
}

int square(int x) {       // определение
    return x * x;
}
```

## Ключевое слово void

Употребляется в двух позициях с разным смыслом:

```c
void print_line(int n) {          // не возвращает значения
    for (int i = 0; i < n; i++) putchar('-');
    putchar('\n');
    // return; — допустимо для досрочного выхода, но без значения
}

int get_value(void) {             // не принимает аргументов
    return 42;
}

void *p;                          // указатель на неопределённый тип
```

> `void` как тип возврата — «результата нет». `void` в списке параметров — «аргументов нет». В C запись `int f()` означает «список параметров не указан», а `int f(void)` — «параметров нет»; это разные вещи.

## Передача аргументов

### По значению (C по умолчанию)

Функция получает **копию**. Изменения внутри не видны снаружи.

```c
void bad_swap(int a, int b) {
    int t = a; a = b; b = t;      // меняются местами только копии
}
```

### Через указатель

```c
void swap(int *a, int *b) {
    int t = *a; *a = *b; *b = t;
}

int x = 1, y = 2;
swap(&x, &y);                     // x = 2, y = 1
```

### По ссылке (только C++)

```cpp
void swap(int &a, int &b) {
    int t = a; a = b; b = t;
}
swap(x, y);                       // без & при вызове
```

## Передача массива в функцию

**Массив всегда передаётся как указатель на первый элемент.** Копирования не происходит.

```c
// Все три записи эквивалентны
void f(int a[10], int n);
void f(int a[],   int n);
void f(int *a,    int n);
```

Следствия:

1. Функция **изменяет исходный** массив — обратной передачи не требуется.
2. Размер теряется: `sizeof(a)` внутри функции даст размер указателя, а не массива. Поэтому длину передают отдельным параметром.

```c
int sum(const int *a, int n) {    // const защищает от случайной записи
    int s = 0;
    for (int i = 0; i < n; i++) s += a[i];
    return s;
}

int main(void) {
    int arr[5] = {1, 2, 3, 4, 5};
    printf("%d\n", sum(arr, 5));  // 15
}
```

Двумерный массив требует указания всех измерений, кроме первого:

```c
void print(int m[][4], int rows);
```

## Перегрузка функций (C++)

Несколько функций с одним именем, различающихся **списком параметров**:

```cpp
int    max(int a, int b)          { return a > b ? a : b; }
double max(double a, double b)    { return a > b ? a : b; }
int    max(int a, int b, int c)   { return max(max(a, b), c); }
```

**Сигнатуру образуют имя и типы параметров.** Тип возвращаемого значения в неё **не входит**:

```cpp
int    f(int x);
double f(int x);      // ОШИБКА: отличается только типом возврата
```

В языке C перегрузки нет — функции с одинаковыми именами недопустимы.

**Параметры по умолчанию** (тоже только C++) задаются справа налево:

```cpp
void draw(int x, int y, int size = 10, char c = '*');
draw(1, 2);            // size = 10, c = '*'
```

## Рекурсия

**Рекурсивная функция** вызывает саму себя. Обязательные части:

1. **Базовый случай** — условие остановки;
2. **Рекурсивный случай** — вызов себя на «уменьшенных» данных.

Без базового случая рекурсия не остановится и переполнит стек.

```c
long long factorial(int n) {
    if (n <= 1) return 1;              // базовый случай
    return n * factorial(n - 1);       // рекурсивный случай
}
```

**Как это выполняется.** Важно понимать, что умножение происходит **не на пути вниз, а на пути обратно**: вызов не может вернуть значение, пока не дождётся результата вложенного вызова, поэтому сначала рекурсия разворачивается до базы, а потом сворачивается, перемножая результаты.

```
    вниз (вызовы)                      вверх (возвраты)

    factorial(4)                        24  = 4 × 6
      └─ factorial(3)                    6  = 3 × 2
           └─ factorial(2)               2  = 2 × 1
                └─ factorial(1)          1  ← базовый случай, стоп
                     n ≤ 1 → return 1

    глубина стека = 4 кадра одновременно
```

`factorial(4)` = 4 · 3 · 2 · 1 = **24**.

**Сложность.** Время **O(n)** — ровно n вложенных вызовов, в каждом одно умножение. Память **O(n)** на стек вызовов, и это главное отличие от цикла, который обошёлся бы O(1).

**Сколько всего вызовов?** Для `f(n)` с базой при `n == 0` вызовы идут для n, n−1, …, 1, 0 — всего **n + 1**.

**Почему наивный `fib` экспоненциален.** У факториала из каждого вызова растёт одна ветка, а у Фибоначчи — две, и дерево вызовов раздваивается на каждом уровне. Одни и те же значения пересчитываются десятки раз:

```
                        fib(5)
                   ╱              ╲
              fib(4)              fib(3)
            ╱       ╲            ╱      ╲
        fib(3)     fib(2)     fib(2)   fib(1)
        ╱    ╲     ╱   ╲      ╱   ╲
    fib(2) fib(1) fib(1) fib(0) fib(1) fib(0)
    ╱   ╲
 fib(1) fib(0)

    fib(3) посчитан 2 раза, fib(2) — 3 раза, fib(1) — 5 раз
    всего 15 вызовов ради 5-го числа  →  O(2ⁿ)

    для fib(50) это порядка 10¹⁵ вызовов — часы работы
    итеративная версия делает 50 сложений  →  O(n)
```

```c
// Числа Фибоначчи — наивно
int fib(int n) {
    if (n <= 1) return n;
    return fib(n - 1) + fib(n - 2);    // O(2ⁿ) — экспоненциально!
}

// Числа Фибоначчи — итеративно, O(n)
int fib_fast(int n) {
    int a = 0, b = 1;
    for (int i = 0; i < n; i++) { int t = a + b; a = b; b = t; }
    return a;
}

// НОД по Евклиду
int gcd(int a, int b) {
    return b == 0 ? a : gcd(b, a % b);
}

// Быстрое возведение в степень, O(log n)
long long power(long long x, int n) {
    if (n == 0) return 1;
    long long half = power(x, n / 2);
    return n % 2 ? half * half * x : half * half;
}
```

### Виды рекурсии

- **Прямая** — функция вызывает себя.
- **Косвенная** — A вызывает B, B вызывает A.
- **Хвостовая** — рекурсивный вызов является последним действием; компилятор может развернуть её в цикл.
- **Древовидная** — несколько рекурсивных вызовов в теле (как у `fib`), число вызовов растёт экспоненциально.

### Рекурсия против итерации

| | Рекурсия | Итерация |
|---|---|---|
| Читаемость на деревьях, графах, «разделяй и властвуй» | Выше | Ниже |
| Расход памяти | Кадр стека на каждый вызов | Константа |
| Скорость | Медленнее (накладные расходы вызова) | Быстрее |
| Риск | Переполнение стека | Зацикливание |

Любую рекурсию можно переписать итеративно, при необходимости — с явным стеком.

### Стек вызовов

Каждый вызов создаёт **кадр стека** (stack frame) с копией локальных переменных, аргументами и адресом возврата. Кадры складываются один на другой, как в обычном стеке, и снимаются в обратном порядке — поэтому рекурсия и «сворачивается» снизу вверх.

```
    во время factorial(1) в памяти лежат все четыре кадра:

    ┌──────────────────────────┐ ← вершина стека
    │ factorial(1)  n=1        │   вернёт 1
    ├──────────────────────────┤
    │ factorial(2)  n=2        │   ждёт результата
    ├──────────────────────────┤
    │ factorial(3)  n=3        │   ждёт результата
    ├──────────────────────────┤
    │ factorial(4)  n=4        │   ждёт результата
    ├──────────────────────────┤
    │ main()                   │
    └──────────────────────────┘

    каждый кадр занимает память, пока вызов не вернулся
```

Глубина рекурсии ограничена размером стека (обычно 1–8 МБ), поэтому `f(1000000)` даст **stack overflow** — памяти на миллион кадров просто нет. Итеративная версия того же алгоритма работает в **O(1)** памяти и такого ограничения не имеет.

**Хвостовая рекурсия** — частный случай, когда рекурсивный вызов является самым последним действием и его результат возвращается без изменений. Тогда старый кадр больше не нужен, и компилятор может переиспользовать его вместо создания нового, превращая рекурсию в цикл с **O(1)** памяти:

```
    обычная (нужен старый кадр)     хвостовая (кадр переиспользуется)
    return n * factorial(n-1);      return helper(n-1, acc*n);
           └─ после возврата надо           └─ после возврата
              ещё умножить                     делать нечего
```

## Быстрая проверка себя

1. Что означает `void` как тип возврата? *(функция не возвращает значения)*
2. Что передаётся при передаче массива в функцию? *(указатель на первый элемент)*
3. По какому признаку различаются перегруженные функции? *(по списку параметров)*
4. Что произойдёт без базового случая в рекурсии? *(переполнение стека)*
5. Какова сложность наивного рекурсивного `fib(n)`? *(O(2ⁿ))*
