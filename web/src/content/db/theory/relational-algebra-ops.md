## Зачем нужна реляционная алгебра

Реляционная алгебра — **процедурный** язык: каждая операция берёт одно или два отношения и возвращает новое отношение. Результат снова можно подать на вход следующей операции — это свойство **замкнутости**.

Именно в терминах реляционной алгебры оптимизатор СУБД переписывает ваш SQL-запрос перед выполнением.

## Базовые (примитивные) операции

Кодд выделил шесть базовых операций, через которые выражаются все остальные:

| Операция | Обозначение | Что делает |
|---|---|---|
| Выборка (селекция) | σ<sub>условие</sub>(R) | Отбирает **строки**, удовлетворяющие условию |
| Проекция | π<sub>атрибуты</sub>(R) | Оставляет указанные **столбцы**, удаляя дубликаты |
| Объединение | R ∪ S | Все кортежи обоих отношений без повторов |
| Разность | R − S | Кортежи R, которых нет в S |
| Декартово произведение | R × S | Все возможные пары кортежей |
| Переименование | ρ | Меняет имя отношения или атрибута |

**Производные** (выражаются через базовые): пересечение, соединение (все виды), деление.

> Типичный вопрос на тесте: *какие операции базовые?* Соединение и пересечение — **не** базовые.

## Теоретико-множественные операции

Требуют **совместимости по схеме** (union-compatible): одинаковое число атрибутов и попарно совместимые домены.

### Объединение R ∪ S

Все кортежи, входящие хотя бы в одно отношение. Дубликаты удаляются.

```sql
SELECT id, name FROM student_kz
UNION
SELECT id, name FROM student_ru;      -- UNION ALL сохраняет дубликаты
```

### Пересечение R ∩ S

Кортежи, входящие в оба отношения. Выражается через разность: `R ∩ S = R − (R − S)`.

```sql
SELECT id FROM enrolled INTERSECT SELECT id FROM paid;
```

### Разность R − S

Кортежи R, отсутствующие в S. **Некоммутативна:** R − S ≠ S − R.

```sql
SELECT id FROM enrolled EXCEPT SELECT id FROM paid;   -- в Oracle: MINUS
```

## Декартово произведение R × S

Каждый кортеж R сцепляется с каждым кортежем S. Совместимость схем **не требуется**.

- Число кортежей: **|R| · |S|** (перемножается)
- Число атрибутов: **степень(R) + степень(S)** (складывается)

> R: 5 кортежей, 3 атрибута. S: 4 кортежа, 2 атрибута.
> R × S: **20 кортежей и 5 атрибутов**. Это готовое тестовое задание.

```sql
SELECT * FROM r CROSS JOIN s;   -- или: SELECT * FROM r, s;
```

## Выборка σ (селекция)

Горизонтальная операция: оставляет **строки** по условию. Схема результата совпадает со схемой исходного отношения.

σ<sub>gpa > 3.5</sub>(Student) → `SELECT * FROM student WHERE gpa > 3.5;`

## Проекция π

Вертикальная операция: оставляет **столбцы**. По определению из результата удаляются дубликаты кортежей (в SQL для этого нужен явный `DISTINCT`).

π<sub>name, gpa</sub>(Student) → `SELECT DISTINCT name, gpa FROM student;`

## Операции над множествами в SQL

Реляционные операции ∪, ∩, − напрямую отражают операции над множествами.
Ключевое свойство множества: **элементы не повторяются, а порядок не имеет значения**.

> `{1,2,3,4,5} ∪ {1,3,4,8,9} = {1,2,3,4,5,8,9}`
>
> Запись `{8,9,5,4,1,2,3}` — **то же самое множество**: порядок не важен.
> А запись `{1,2,3,4,5,1,3,4,8,9}` множеством не является — в ней повторы.

То же и с результатом `SELECT` без `ORDER BY`: порядок строк не определён,
поэтому две выдачи с одними и теми же строками в разном порядке равноценны.

## Соединение (JOIN)

**Тета-соединение** R ⋈<sub>θ</sub> S — декартово произведение с последующей выборкой по условию θ:

R ⋈<sub>θ</sub> S = σ<sub>θ</sub>(R × S)

**Эквисоединение** — частный случай, где θ — только равенства.

**Естественное соединение** R ⋈ S — эквисоединение по всем одноимённым атрибутам, при этом дублирующийся столбец остаётся в одном экземпляре.

**Внешние соединения** (левое, правое, полное) дополняют несовпавшие кортежи значениями `NULL`.

| Реляционная алгебра | SQL |
|---|---|
| R ⋈<sub>R.a = S.b</sub> S | `INNER JOIN s ON r.a = s.b` |
| R ⋈ S (естественное) | `NATURAL JOIN s` |
| R ⟕ S (левое внешнее) | `LEFT OUTER JOIN` |
| R ⟖ S (правое внешнее) | `RIGHT OUTER JOIN` |
| R ⟗ S (полное внешнее) | `FULL OUTER JOIN` |

## Деление R ÷ S

Самая неинтуитивная операция — и потому любимая составителями тестов.

Пусть R(A, B) и S(B). Тогда **R ÷ S** — множество значений A, которые в R связаны со **всеми** значениями B из S.

- Схема результата: атрибуты R, отсутствующие в S.
- Смысл: запросы вида «найти тех, кто связан со **всеми**…».

**Пример.** Есть `Сдал(студент, предмет)` и `Предмет(предмет)`. Тогда

`Сдал ÷ Предмет` = студенты, сдавшие **все** предметы.

| Сдал | | | Предмет |
|---|---|---|---|
| студент | предмет | | предмет |
| Айгуль | БД | | БД |
| Айгуль | Алгоритмы | | Алгоритмы |
| Ержан | БД | | |

Результат: **Айгуль** (Ержан не сдал «Алгоритмы»).

В SQL деление выражается через двойное `NOT EXISTS`:

```sql
SELECT DISTINCT s.student
FROM passed s
WHERE NOT EXISTS (
    SELECT 1 FROM subject sub
    WHERE NOT EXISTS (
        SELECT 1 FROM passed p
        WHERE p.student = s.student AND p.subject = sub.subject
    )
);
-- «нет такого предмета, который бы этот студент не сдал»
```

## Сводная шпаргалка

| Операция | Требует совместимости схем? | Число кортежей результата |
|---|---|---|
| Объединение ∪ | **Да** | ≤ \|R\| + \|S\| |
| Пересечение ∩ | **Да** | ≤ min(\|R\|, \|S\|) |
| Разность − | **Да** | ≤ \|R\| |
| Декартово произведение × | Нет | \|R\| · \|S\| |
| Выборка σ | — (одно отношение) | ≤ \|R\| |
| Проекция π | — (одно отношение) | ≤ \|R\| |
| Соединение ⋈ | Нет | ≤ \|R\| · \|S\| |
| Деление ÷ | Нет (S ⊂ R по схеме) | Обычно много меньше \|R\| |

## Быстрая проверка себя

1. Какие операции требуют совместимости отношений по схеме? *(∪, ∩, −)*
2. Является ли соединение базовой операцией? *(нет, производная)*
3. R содержит 4 кортежа и 2 атрибута, S — 3 кортежа и 3 атрибута. Каков размер R × S? *(12 кортежей, 5 атрибутов)*
4. Коммутативна ли разность? *(нет)*
5. Какую задачу решает деление? *(«найти связанных со всеми»)*
