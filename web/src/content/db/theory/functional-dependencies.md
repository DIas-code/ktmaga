## Функциональная зависимость

**X → Y** («X функционально определяет Y», X — **детерминант**, Y — зависимая часть) означает:

> если у двух кортежей совпадают значения атрибутов X, то у них обязательно совпадают и значения Y.

Иначе говоря, каждому значению X соответствует **ровно одно** значение Y.

**Важно:** зависимость **направленная**. Из X → Y не следует Y → X.

**Примеры:**

- `ИИН → ФИО` — по ИИН однозначно определяется человек;
- `ФИО → ИИН` — **неверно**: полные тёзки существуют;
- `(номер_заказа, номер_товара) → количество`;
- `номер_товара → название_товара`.

### Виды зависимостей

- **Тривиальная**: Y ⊆ X (например, AB → A). Выполняется всегда, интереса не представляет.
- **Полная**: X → Y, и ни одно собственное подмножество X не определяет Y.
- **Частичная**: X составной, и Y определяется уже частью X. *Нарушает 2НФ.*
- **Транзитивная**: X → Y, Y → Z, при этом Y не ключ ⇒ X → Z. *Нарушает 3НФ.*

## Аксиомы Армстронга

Полная и непротиворечивая система правил вывода:

| Правило | Формулировка |
|---|---|
| **Рефлексивность** | Если Y ⊆ X, то X → Y |
| **Пополнение (аугментация)** | Если X → Y, то XZ → YZ |
| **Транзитивность** | Если X → Y и Y → Z, то X → Z |

Из них выводятся производные правила:

| Правило | Формулировка |
|---|---|
| **Объединение** | X → Y и X → Z ⇒ X → YZ |
| **Декомпозиция** | X → YZ ⇒ X → Y и X → Z |
| **Псевдотранзитивность** | X → Y и WY → Z ⇒ WX → Z |

> **Симметричности среди правил нет.** «Если X → Y, то Y → X» — самый частый неверный вариант в тестах.

## Замыкание множества атрибутов X⁺

**X⁺** — все атрибуты, которые функционально определяются из X по заданному набору зависимостей F.

**Алгоритм:**

1. Положить X⁺ = X.
2. Пока что-то меняется: если есть зависимость A → B, где A ⊆ X⁺, добавить B в X⁺.
3. Результат — X⁺.

**Зачем нужно:** X — суперключ тогда и только тогда, когда X⁺ = все атрибуты отношения.

### Пример разбора

Отношение **R(A, B, C, D)**, зависимости **F = {A → B, B → C}**.

```
A⁺  = {A}
    → добавляем B (по A → B)   = {A, B}
    → добавляем C (по B → C)   = {A, B, C}
    D не добавляется — его ничто не определяет
A⁺  = {A, B, C} ≠ все атрибуты ⇒ A не ключ
```

```
{A,D}⁺ = {A, D}
       → + B  = {A, D, B}
       → + C  = {A, D, B, C}   = все атрибуты  ⇒  {A, D} — суперключ
```

Минимален ли он? Проверим части: A⁺ = {A,B,C} — нет; D⁺ = {D} — нет. Значит **{A, D} — потенциальный ключ**.

## Выделение первичного ключа из потенциального

**Порядок действий:**

**Шаг 1. Найти атрибуты, обязательно входящие в любой ключ.** Это те, что **не встречаются ни в одной правой части** зависимостей. В примере выше это `D` — его нечем вывести, значит без него замыкание никогда не даст все атрибуты.

**Шаг 2.** Вычислить замыкание этого «обязательного ядра». Если оно уже даёт все атрибуты — ключ найден.

**Шаг 3.** Иначе добавлять к ядру по одному другие атрибуты и проверять замыкание, пока не получим все атрибуты.

**Шаг 4. Проверить минимальность:** ни одно собственное подмножество не должно давать полного замыкания.

**Шаг 5.** Если потенциальных ключей несколько, **первичным** выбирают один из них — по практическим соображениям:

- меньше атрибутов (простой лучше составного);
- короче и стабильнее значения (не меняются со временем);
- не допускает `NULL`;
- не несёт смысловой нагрузки (иногда предпочитают суррогатный `id`).

Остальные потенциальные ключи становятся **альтернативными** и получают ограничение `UNIQUE`.

```sql
CREATE TABLE student (
    id   INT PRIMARY KEY,        -- выбранный первичный (суррогатный)
    iin  CHAR(12) UNIQUE NOT NULL,  -- альтернативный ключ
    email VARCHAR(80) UNIQUE        -- ещё один альтернативный
);
```

## Виды ключей — полная классификация

Помимо суперключа, потенциального, первичного и внешнего, различают:

| Ключ | Что это |
|---|---|
| **Простой** | Состоит из одного атрибута |
| **Составной (сложный)** | Из двух и более атрибутов |
| **Естественный** | Взят из предметной области и **несёт смысл сам по себе**: ИИН, номер паспорта, артикул |
| **Суррогатный (искусственный)** | Сгенерированное значение без смысла: автоинкрементный `id`, GUID |
| **Альтернативный** | Потенциальный ключ, не выбранный первичным |
| **Вторичный** | Атрибут для поиска, уникальность **не** гарантирует |
| **Рекурсивный** | Внешний ключ, ссылающийся на ту же таблицу (`manager_id → employee.id`) |

**Естественный против суррогатного** — это выбор с последствиями:

| | Естественный | Суррогатный |
|---|---|---|
| Смысл | Есть | Нет |
| Стабильность | Может измениться (фамилия, телефон) | Никогда не меняется |
| Размер | Часто длинный | Компактный |
| Понятность в запросах | Выше | Ниже, нужны соединения |
| Риск утечки данных | Ключ виден в URL и логах | Безопаснее |

На практике чаще берут суррогатный первичный ключ, а естественный делают `UNIQUE` —
так сохраняются оба преимущества.

## Термины про атрибуты

- **Ключевой (прайм-)атрибут** — входит хотя бы в один потенциальный ключ.
- **Неключевой** — не входит ни в один.

Эти понятия нужны для определений 2НФ и 3НФ.

## Ещё один разбор

**R(Студент, Курс, Преподаватель, Оценка)**, зависимости:
- (Студент, Курс) → Оценка
- (Студент, Курс) → Преподаватель
- Преподаватель → Курс

Атрибуты, не встречающиеся справа: **Студент** — значит он входит в любой ключ.

- `Студент⁺` = {Студент} — мало.
- `{Студент, Курс}⁺` = {Студент, Курс, Оценка, Преподаватель} = все ⇒ **потенциальный ключ**.
- `{Студент, Преподаватель}⁺` = {Студент, Преподаватель, Курс, Оценка} = все ⇒ **ещё один потенциальный ключ**.

Прайм-атрибуты: Студент, Курс, Преподаватель. Неключевой: Оценка.

Обратите внимание: зависимость `Преподаватель → Курс` имеет детерминантом не ключ целиком, а часть ключа — отношение в 3НФ, но **не в НФБК**. Это классический пример.

## Быстрая проверка себя

1. Следует ли из X → Y, что Y → X? *(нет)*
2. Как проверить, что X — суперключ? *(вычислить X⁺ и сравнить со всеми атрибутами)*
3. Какие атрибуты обязаны входить в любой потенциальный ключ? *(те, что не встречаются в правых частях зависимостей)*
4. Чем потенциальный ключ отличается от суперключа? *(минимальностью)*
5. Отношение R(A,B,C), F = {AB → C, C → A}. Является ли {A,B} ключом? *(да: {A,B}⁺ = {A,B,C})*
